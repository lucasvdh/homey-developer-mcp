// MCP server for Homey app developers

Ask your AI assistant why your Homey app crashes.

Crashes, user-submitted diagnostic reports, builds and install stats of your own Homey apps, straight from Athom's apps API into Claude, Cursor, VS Code or any other MCP client. Optionally release builds and submit them for certification too.

$ claude mcp add homey-developer --env HOMEY_PAT=pat-... -- npx -y homey-developer-mcp

#Things to ask

The tools are built for questions you'd otherwise answer by clicking through the developer tools site, build by build.

What are the most frequent crashes of my app, and where in my code do they come from?get_crashes
Summarise the diagnostic reports from this week and tell me which ones share a cause.list_diagnostic_reports
Did the crash rate go down since build 41?list_builds · get_crashes
Is my latest build through processing yet? What did the reviewer say?get_build_status
Release build 42 to test, then submit it for certification.release_build · submit_for_certification
How are installs of my apps trending over the last 30 days?list_apps · get_install_stats

#Tools

Read tools are always available. They cover your own apps and the apps of every Developer Organization you're in.

ToolWhat it returns
list_appsYour apps with live and test version, installs, rating and crash counts per build.
list_buildsappId, limit?Builds of an app, newest first, with state, installs and crashes.
get_crashesappId, builds?, buildId?, kind?, limit?Crashes and unhandled rejections, grouped by error and the file and line in your own code. Errors that only differ in a device id count as one.
list_diagnostic_reportsappId, builds?, buildId?Reports users sent with Create diagnostics report: Log ID, their message and a preview of stderr.
get_diagnostic_reportappId, logId, builds?One report in full: user message, stdout and stderr.
get_build_statusappId, buildIdState of a build, why processing failed, reviewer comments and Athom's AI review.
get_install_statsappId, days?, perDriver?Daily installs, optionally per driver.

Write tools

Only registered when you set HOMEY_MCP_ALLOW_WRITE=1. Without it, your assistant doesn't even see them. They are marked destructive, so clients that support it ask before every call.

release_buildappId, buildId, channelPuts a build on the test or live channel. Athom only accepts live for a build that passed review.
submit_for_certificationappId, buildId, autoRelease?Sends a build to Athom for review. autoRelease defaults to false, so going live stays a separate step.
retract_submissionappId, buildIdWithdraws a build from review.

#Install

You need Node.js 18 or newer and your Athom Personal Access Token. Nothing to clone or build: your MCP client starts the server with npx.

  1. Copy your Personal Access Token

    Open tools.developer.homey.app/me, scroll to Personal Access Token and copy it. It starts with pat-. It's the same token the Homey CLI uses in CI, so treat it like a password.

  2. Add the server to your client 
    $ claude mcp add homey-developer --env HOMEY_PAT=pat-... -- npx -y homey-developer-mcp

    Add --scope user to use it in every project. To enable the write tools, add --env HOMEY_MCP_ALLOW_WRITE=1. Check it's connected with /mcp.

    Settings → Developer → Edit Config opens claude_desktop_config.json. Add the server and restart Claude Desktop.

    {
  "mcpServers": {
    "homey-developer": {
      "command": "npx",
      "args": ["-y", "homey-developer-mcp"],
      "env": { "HOMEY_PAT": "pat-..." }
    }
  }
}

    Add this to ~/.cursor/mcp.json for every project, or .cursor/mcp.json for one.

    {
  "mcpServers": {
    "homey-developer": {
      "command": "npx",
      "args": ["-y", "homey-developer-mcp"],
      "env": { "HOMEY_PAT": "pat-..." }
    }
  }
}

    Add this to .vscode/mcp.json. VS Code asks for the token the first time and stores it securely, so it never ends up in the file.

    {
  "inputs": [
    { "type": "promptString", "id": "homey-pat", "description": "Athom Personal Access Token", "password": true }
  ],
  "servers": {
    "homey-developer": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "homey-developer-mcp"],
      "env": { "HOMEY_PAT": "${input:homey-pat}" }
    }
  }
}

    Any client that runs stdio MCP servers works. Point it at this command and pass the token as an environment variable:

    $ HOMEY_PAT=pat-... npx -y homey-developer-mcp
  3. Ask away

    Start with "List my Homey apps" to check the token works, then try one of the questions above.

Configuration

HOMEY_PATRequired. Your Athom Personal Access Token.
HOMEY_MCP_ALLOW_WRITESet to 1 to enable release_build, submit_for_certification and retract_submission.

#How it works

The server exchanges your token for a short-lived apps API token, the same way the Homey CLI does, and calls apps-api.athom.com. Athom returns three kinds of entries from one crash endpoint. The server tells them apart by how the entry opens:

Diagnostic report

Sent by a user from your app's settings. Split into Log ID, their message, stdout and stderr.

Note: this log has been manually submitted by a user.
Unhandled rejection

A promise you didn't catch. Didn't necessarily crash the app, but counted every time.

Note: this e-mail is sent because an unhandledRejection occurred…
Crash

Everything else: the stack trace itself, starting with the error.

TypeError: Cannot read properties of undefined…

Homey groups crashes by their exact stack, so an error that mentions a device id gets a separate group per device. get_crashes regroups them by error message and the first frame in your own code, so the counts add up per actual bug. Reports and crashes are stored on the build the user was running; the tools look at your newest 5 builds unless you ask for more.

Waiting for a build

An MCP server only answers when called, so it can't notify you. In Claude Code, run /loop with get_build_status while you wait. For a push notification on your phone, use the flow triggers of App Insights for Developers on your Homey.

Privacy. Diagnostic reports contain what your users wrote and your app's logs from their Homey, including device names. Whatever the tools return reaches the AI assistant you connect. Only connect one you're comfortable sharing that with.
